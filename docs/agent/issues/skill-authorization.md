# [Agent] Skill 权限校验与租户隔离

## 背景

上层可以按请求传递 Skill ID，但不能因此扩大 Agent 或调用用户的权限范围。需要建立 Agent、用户、租户三者共同约束的授权模型。

## 当前处理

第一阶段仅允许 AgentDefinition 中静态绑定的 Skill；运行请求中的临时 Skill ID 不生效。这样先保证功能边界明确，不引入动态授权绕过。

## 后续要做

- 定义 `请求 Skill ∩ Agent 白名单 ∩ 用户权限 ∩ 租户权限` 的授权规则；
- 为读取、写入和高风险 Skill 定义不同审批策略；
- 在 Tool 执行上下文传递用户、租户和审计身份；
- 拒绝原因使用统一错误码，避免泄漏未授权资源信息；
- 增加跨租户、伪造 Skill ID、禁用 Agent 和权限变更的回归测试。

## 验收标准

- 请求无法启用 Agent 未绑定的 Skill；
- 不同租户无法借 Agent 调用彼此资源；
- 高风险 Skill 在无授权或无确认时不产生副作用；
- 审计记录能定位 Agent、运行、用户、租户和实际 Skill。
