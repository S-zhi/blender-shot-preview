# Agent 运行限制（第一阶段）

限制由 Agent Runner 包装层强制执行；不能依赖 Prompt 或模型自行停止。模型网关后续可额外实施 token 和金额配额，但 Agent 侧先限制运行规模。

| 限制 | 同步运行默认值 | 异步作业默认值 | 达到限制后的行为 |
|---|---:|---:|---|
| 模型调用次数 | 12 | 40 | 停止并返回 `AGENT_MODEL_CALL_LIMIT` |
| 工具调用总次数 | 12 | 40 | 停止并返回 `AGENT_TOOL_CALL_LIMIT` |
| 同一工具调用次数 | 4 | 8 | 停止并返回 `AGENT_REPEATED_TOOL_LIMIT` |
| 连续工具失败次数 | 3 | 5 | 停止并返回最后一个安全错误 |
| 总运行时间 | 2 分钟 | 20 分钟 | 取消上下文并标记 `TIMEOUT` |
| 单个工具时间 | 30 秒 | 2 分钟 | 取消该工具并按错误策略处理 |
| 单次工具结果大小 | 256 KiB | 1 MiB | 截断禁止；返回 `TOOL_LIMIT_EXCEEDED` |
| 单次模型最大输出 | 4,096 tokens | 8,192 tokens | 在模型请求中设置输出上限 |

这些值故意留有余量：普通多步 Agent 有最多 12 次模型和工具交互，异步作业可完成较长链路；同时避免工具循环、重复失败和异常大结果无限占用资源。

实现要求：

- 每次模型调用、工具调用和失败都更新 `AgentRun` 计数；
- 每次运行使用带总超时的 `context.Context`，每个 Tool 使用更短的子 context；
- 触发限制时发布 `AgentFailed` 事件，带稳定错误码，不再调用模型或工具；
- 记录实际计数、耗时和限制命中原因；
- 模型网关可在将来根据 token 使用和费用再拒绝请求，Agent 必须把这类拒绝映射为 `AGENT_BUDGET_EXCEEDED`。
